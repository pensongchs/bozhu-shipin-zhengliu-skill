# 跨工具可用性

学员会把这个 Skill 装在不同工具里。抓取能力差异很大，但**指令本身与工具无关**：只要能把素材和指令喂进去，任何模型都能产出报告和一期方案。

## 两类能力

| 能力 | 决定什么 | 没有时 |
|---|---|---|
| 本地文件读写 | 能不能建档、渲染 HTML、跑校验 | 归档环节不可用，直接输出 Markdown 让用户保存 |
| 浏览器／电脑控制 | 能不能自动翻主页、截图、取字幕 | 走素材包模式，或只做文本蒸馏 |

## 能力矩阵

以实际版本为准；平台风控和登录态会随时变化。

| 工具 | 自动抓取 | 本地文件 | 推荐路径 |
|---|---|---|---|
| Codex | 有（浏览器控制） | 有 | 全自动 |
| DeepSeek Harness | 有（cua） | 有 | 全自动 |
| Claude（Computer Use／Claude Code） | 有 | 有 | 全自动 |
| ChatGPT（含浏览） | 部分，登录态平台常受限 | 有 | 半自动：用户导出素材 |
| Gemini | 部分 | 有 | 半自动 |
| DeepSeek 网页／App | 无 | 上传文件 | 纯文本：只做选题／文案 |
| 豆包 | 部分 | 上传文件 | 半自动 |
| Kimi | 可读链接与文件 | 上传文件 | 半自动 |
| 通义／智谱 | 部分 | 上传文件 | 半自动 |
| Cursor 等 IDE Agent | 取决于浏览器 MCP | 有 | 半自动或全自动 |

## 三档降级方案

**A 全自动**：能控制浏览器 + 能读写文件。按 SKILL.md 全流程走。

**B 半自动**：不能抓，但能读文件。要求用户提供最小素材包：

- 主页截图（粉丝、获赞、作品数、简介）；
- Top10 每期的标题、数据截图；
- Top10 每期 3 帧画面截图；
- 3—5 条逐字稿或字幕文件；
- 发布时间、时长。

**C 纯文本**：只能对话。只做选题与文案两个板块，画面标注「未获取」；总指令仍然可用，但分镜表只能给「画面类型建议」，不能给具体构图。

## 指令卫生（保证跨模型稳定）

1. 纯 Markdown 或纯文本，不用 XML 标签、不用函数调用格式。
2. 变量统一用【】，一次只留一处空。
3. 单条指令 ≤3000 字；总指令过长时拆成「选题 → 文案 → 分镜」三次投喂。
4. 输出格式写死：固定小标题、固定表格列名。
5. 一次只给一个板块的素材，不要把 30 条视频和全部指令一次性塞进去。
6. 不写「你是顶级文案大师」这类空泛人设，写具体规则。

## 模型差异与应对

| 差异 | 表现 | 应对 |
|---|---|---|
| 中文短视频语感 | 海外模型容易写成书面语 | 在指令里给 2—3 个原博主的句式样例（意译，不抄原句） |
| 长文稳定性 | 超过 3000 字容易掉结构 | 分段投喂，每段只要求一个输出 |
| 表格稳定性 | 列数多时错位 | 明确列名和列数，要求先输出表头 |
| 自检执行 | 容易跳过 | 把自检项编号，要求逐条回答「是／否」 |

## 回测（交付前必做）

拿这个博主已经发过的一条爆款，遮住标题和数据，让 AI 按总指令重做一版，再和原片对比：

- 选题是否落在同一决策点；
- 开头是否在 3 秒内给出冲突；
- 结构是否同构；
- 分镜是否可拍。

复现不了，说明指令没写到点子上，回炉改指令，不要怪模型。
